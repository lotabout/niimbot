# B1 6.19 密度可控补丁 —— 移植台账（density → coefficient）

> 目标机：Niimbot B1，HW 6.01 / FW 6.19。
> 上游方案：ThreeDaPrint/niimbot 的 `B1_5.22_density_coeff.bin`（fw 5.22，md5 `023ff56326fe8c65f01b68f32ebdba99`）。
> 本文记录"把上游 5.22 的 Cortex-M0 code-cave 方案换址移植到 6.19"的全部依据与验证状态。
> 生成物：`fw/B1_6.19_density_coeff.bin`（md5 `43065da9717c4ba533c6669cc7a8e9b9`）。

## 0. 结论

6.19 与 5.22 **同构**：两个 renderer 入口、soft-float 乘法例程、配置结构体布局都逐条对应，
因此移植 = 换址，不需要重新设计 detour。产出镜像 = 6.19 满能量基线 + 4 处代码注入。

**上游 5.22 的 cave 编码器已被逐字节锚定**：用本文同一套编码器（`build/build_b1_619_density.py`
的 `enc_bl` / `build_cave_a` / `build_cave_b`）只把地址换成 5.22 的地址，从原厂
`B1_5.22.bin` 重建，输出与上游成品 **0 字节差异**（`repro/reproduce_522_density.py`）。
所以 6.19 侧唯一的不确定项只剩"地址换得对不对"，而这一点有独立证据（§2/§3）。

## 1. 地址对照表（5.22 → 6.19）

| 项目 | 5.22 | 6.19 | 偏移 | 判定依据 |
|---|---|---|---|---|
| base 系数组（4 个 float） | `0x01011dec` | `0x01011e60` | +0x74 | 原值 74.4/60.0/60.8/120.0 逐一相同 |
| renderer A 系数（6 个 float） | `0x01016538` | `0x01016600` | +0xC8 | 原值 20/50/30/150/100/90 逐一相同 |
| renderer B 系数（5 个 float） | `0x01016c84` | `0x01016d4c` | +0xC8 | 原值 10/30/50/120/100 逐一相同 |
| **renderer A 入口** | `0x01016124` | `0x010161ec` | +0xC8 | 前 20 条指令**逐字节相同**（含入口 `push {r0-r7,lr}`） |
| **renderer B 入口** | `0x01016844` | `0x0101690c` | +0xC8 | 同上，前 20 条逐字节相同 |
| **soft-float 乘法例程** | `0x0102529a` | `0x01026156` | +0xEBC | 函数前 48 字节**逐字节相同** |
| **density 配置字节** | `0x00020704` | `0x00020740` | +0x3C | 见 §3 |
| line-period 表 64×u16 | `0x0102c2a4` | `0x0102d21c` | +0xF78 | 64 项值逐一相同 |

**hook 点** = 入口 + 2（入口 `push` 之后），5.22 与 6.19 相同：

| hook | 6.19 地址 | 覆盖的原字节 | 原指令 |
|---|---|---|---|
| hook124 | `0x010161ee` | `16 46 ff 36` | `mov r6,r2` / `adds r6,#0xff` |
| hook844 | `0x0101690e` | `14 46 06 46` | `mov r4,r2` / `mov r6,r0` |

两个入口都是 `push {r0-r7,lr}`（9 寄存器），所以 detour 的栈偏移与 5.22 完全一致：
renderer A 的输入 arg5 在 `[sp,#0x38]`；renderer B 的 arg6/arg7 在 `[sp,#0x3c]`/`[sp,#0x40]`。

## 2. 三级证据链

1. **成品锚定（最强）** —— `repro/reproduce_522_density.py`：同一编码器 + 同一规则作用在
   原厂 5.22 上，逐字节复现上游 density 成品（0 差异）。锚定了：15 float→400、
   line-period `floor(old*1.5)`、2 处 RFID、`bl` 编码、detour 的 `push/pop` 与栈偏移、
   位移指令重放、m-table 字节、cave 布局。
2. **同构反汇编** —— 6.19 对应函数与 5.22 逐条相同（上表），说明结构与寄存器约定未变。
3. **运行期引用确认** —— 6.19 侧各地址由代码自身的引用链确认：
   - `0x01010d88` 的配置校验器对 `[r3,#4]` 做 `subs #1; cmp #5` 范围检查并回写默认值 3，
     `[r3,#5]`→1..3 默认 2，`[r3,#6]`→1..5 默认 1；`r3` 由字面量池载入 = **`0x0002073c`**。
     5.22 对应函数 `0x01010d1a` 的同位置字面量 = `0x00020700`，函数体逐条相同。
   - `0x01022a78` 的 SetDensity 处理函数校验报文 `45 04 00 06`、把 payload[4] 限制在 1..5 后
     执行 `strb`；其 `ldr r1,[pc,#0xd0]` 字面量实测 = **`0x0002073c`**（5.22 侧 `0x01021db0` 的同一位置 = `0x00020700`）。
   - 0x207 段相邻变量的引用计数也整体 +0x3C 对应：`0x20600→0x2063c`、`0x20604→0x20640`、
     `0x20628→0x20664`、`0x206c0→0x206fc`、`0x20700→0x2073c`。
   ⇒ **density 字节 = `0x00020740`**（CFG+4）。

## 3. cave 选址（6.19 零区扫描）

规则：整段全零字节，且**无任何** `ldr` 字面量值命中、无 `b`/`bl`/`adr` 目标命中
（扫描面：全镜像 2 字节对齐线性解码；命中集合 3993 个目标）。
6.19 中满足 ≥48 字节且零引用的只有两处：

| 零区 | 长度 | 用途 | 实际占用 |
|---|---|---|---|
| `0x0102cb62`–`0x0102cbb7` | 86 B | cave A（scale + m-table + 字面量池），起点 4 对齐 `0x0102cb64` | 68 B（余 16） |
| `0x0102c1ed`–`0x0102c21d` | 49 B | cave B（det124+det844），起点 `0x0102c1ee` | 44 B（余 4） |

其余候选零区均被引用（例如 `0x0102b6bd`–`0x0102b759` 157 B 内有 2 个被引用地址），
**不要**改用它们。

## 4. 6.19 注入点清单

| 站点 (vaddr) | file off | 原字节 | 注入后 | 含义 |
|---|---|---|---|---|
| `0x010161ee` | `0x61ee` | `16 46 ff 36` | `15 f0 fe ff` | `bl det124`（cave B） |
| `0x0101690e` | `0x690e` | `14 46 06 46` | `15 f0 77 fc` | `bl det844`（cave B+18） |
| `0x0102cb64` | `0x1cb64` | 全零 68 B | cave A | `scale` + m-table + 池（`0x00020740` / `0x0102cb88` / `0x01026157`） |
| `0x0102c1ee` | `0x1c1ee` | 全零 44 B | cave B | `det124` / `det844` |

加上基线（15 float + 64 line-period + 2 RFID = 192 字节覆盖）后：
相对原厂 6.19 共 **270 字节变化，31 个差异区，允许区域外 0 字节**。

## 5. 复现与验证

```bash
# 只读验证（10 项，含 capstone 反汇编回读）
python3 repro/verify_b1_619_density.py

# 从原厂 6.19 重建
python3 build/build_b1_619_density.py --src fw/B1_6.19.bin --out fw/B1_6.19_density_coeff.bin

# 根证据：用同一编码器复现上游 5.22 成品（应 0 字节差异）
python3 repro/reproduce_522_density.py
```

验证器覆盖：源 md5/大小、候选大小、15 系数、64 项 line-period、2 处 RFID、
hook `bl` 字面量与解码目标、cave 与重建字节一致、capstone 回读（bl 目标 / 栈偏移 /
位移指令）、差异区域约束、md5/sha256。

## 6. 未验证项（不要写成已证明）

1. **U1 能量值标定**：`m-table` 与 400.0 都来自上游在 **5.22** 上的经验标定
   （200 淡 / 250 不实 / 325 接近 / 370 差不多 / 400 实心 / 500 实心 / 700 仍实心）。
   6.19 的打印头批次、供电、纸材是否一致未知 —— D5 是否"实心而不过烧"只能上机 A/B。
2. **U2 时序**：line-period ×1.5 在上游 5.22 硬件上验证过安全（×2 丢行），6.19 未验证。
3. **U3 双色纸**：基线把 renderer A 的 6 个系数也拉到 400，红/黑双色纸的红档显色很可能失效
   （双色 = 单色打印头 + 双层热敏纸，靠能量窗口分档）。若要保双色，需要跳过 renderer A 的
   6 个系数（上游 density 方案同样未处理这一点）。
4. **本候选从未刷入任何设备、从未打印** —— 全部结论来自静态分析与成品复现。
5. `.s`/`.ld` 是等价汇编源，**未在本机用 arm-none-eabi 汇编**（本机无该工具链）；
   权威字节是 `build/build_b1_619_density.py` 的输出，其编码器已被 §2 的成品复现锚定。
